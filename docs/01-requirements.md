# 01. 要件

R1 の仕様をそのまま引き継ぐ。R1 でコードに暗黙に書かれていたルールもここで明文化する。
R2 で挙動を変える点には **【R2】** を付けた。

## 1. 施設

| 項目 | 値 |
|---|---|
| 名称 | FUTSAL PARK（屋内人工芝フットサルコート） |
| コート数 | 1面 |
| 営業時間 | 10:00〜22:00（1時間単位の枠: 10時枠〜21時枠の12枠） |
| 料金 | 平日 / 土日で時間単価が異なる（初期値: 平日 4,000円/h、土日 5,000円/h）。管理者が変更できる |
| 定休日 | 曜日で指定（初期値: 月曜）。管理者が変更できる。複数曜日可 |

- 施設情報（名称・電話番号・住所・メールアドレス）は1か所で管理し、画面とメールで同じ値を使う **【R2】**

## 2. ユーザー

| ロール | できること |
|---|---|
| ゲスト | 施設情報・空き状況の閲覧、会員登録、ログイン |
| 会員（`user`） | 予約・自分の予約の一覧・キャンセル、プロフィール編集 |
| 管理者（`admin`） | 全予約の閲覧・キャンセル、電話予約の代理登録、料金・定休日・臨時休業日の設定、ユーザー検索、プロフィール編集 |

- 管理者アカウントはシーダーで作る（画面からは作れない）
- 会員登録で作られるのは常に `user`

### 会員登録・プロフィール

| 項目 | ルール |
|---|---|
| 名前 | 必須、20文字以内 |
| メールアドレス | 必須、メール形式、255文字以内、一意 |
| パスワード | 必須、8文字以上、確認入力と一致 |

- 登録と同時にログイン状態になる
- プロフィール編集で名前・メールを変更できる。パスワードを変えるときは現在のパスワードが必要

## 5. 利用規約（トップに表示）

**【R2】** キャンセル料の項目を実態に合わせて変える。

- ご予約のキャンセルは、ご利用開始時刻までにマイページから行ってください。キャンセル料はかかりません。
- コート内での飲食（フタ付きの飲料は可）、喫煙は禁止です。
- 施設・備品を破損・紛失された場合は、実費をご請求させていただきます。
- その他、スタッフの指示に従ってご利用ください。

R1 の文言は「キャンセルは24時間前まで」「24時間以内は利用料金の100%」だった。

## 6. 管理者の操作

### 6.1 予約カレンダー

- 週単位のカレンダーで予約状況を見る。予約済みの枠には予約者名を表示する
- 過去 **3か月前** まで遡って見られる。未来は制限なし（ただし予約できる範囲はルールどおり）
- 定休日・臨時休業日・期間外の日でも、予約が残っていれば予約者名を表示し、詳細確認・キャンセルができる **【R2】**（定休日を後から増やしたときに残った予約を扱えるように）
- 予約済みの枠をクリック → 予約詳細（予約者名・日時・料金）→ キャンセルできる
- 空き枠を選ぶ → 予約者名を入力して **電話予約** を代理登録できる
  - 電話予約は会員と紐づかない（`user_id = null`）
  - 適用するルール: 会員と同じ（R1〜R7, R9）
  - 適用しないルール: R8（1人1日1件）のみ
  - **【R2】** R1 は API 上は R4（1か月制限）・R6（定休日・休業日）も免除していたが、管理カレンダーではその枠を選べず、使えない例外になっていた。画面と API をそろえる（2026-09-29 決定）
- 管理者が会員の予約をキャンセルした場合、会員にキャンセルメールを送る

### 6.2 料金設定

- 平日 / 土日の時間単価を変更する（0円以上の整数）
- 変更は **これから作られる予約** にだけ効く（既存予約の金額は変えない）

### 6.3 定休日設定

- 曜日を複数選んで保存する（全て外すと定休日なし）
- 既存の予約はそのまま（R1 と同じ）。定休日にした曜日の既存予約は管理者が個別に対応する

### 6.4 臨時休業日

- 日付と理由（任意、255文字以内）を登録・削除できる
- 登録できるのは **今日以降** の日付のみ。一覧も今日以降のみ表示 **【R2】**（R1 は過去日も登録・表示できた）
- 登録しようとした日に、確定済みで **まだ開始していない** 予約がある場合:
  1. 件数を示して確認を求める
  2. 管理者が承認したら、それらの予約を **すべてキャンセル** して休業日を登録する（一括・全部成功か全部失敗か）**【R2】**
  - 当日を休業日にするとき、開始済み（利用中・利用済み）の予約はキャンセルせずに残す **【R2】**
  3. 会員の予約には「施設都合キャンセル」メール（理由入り）を送る
- 同じ日を二重に登録することはできない
- 休業日を削除しても、キャンセルした予約は戻らない

### 6.5 ユーザー検索

- 名前またはメールアドレスの部分一致で会員（`user` ロール）を検索する
- 結果は最大20件。名前・メール・確定済み予約の件数を表示する

## 7. 画面

R1 と同じ構成。

| パス | 画面 | 閲覧できる人 |
|---|---|---|
| `/` | トップ（Hero・施設情報・週間カレンダー・利用規約） | 全員 |
| `/login` | ログイン | ゲスト（ログイン済みなら管理者は `/admin`、会員は `/` へ） |
| `/register` | 会員登録 | ゲスト（同上） |
| `/mypage` | 今後の予約一覧・キャンセル・プロフィール設定 | 会員（未ログインは `/login`、管理者は `/admin` へ） |
| `/admin` | 予約カレンダー・料金・定休日・臨時休業日・ユーザー検索・プロフィール設定 | 管理者（未ログインは `/login`、会員は `/` へ） |

### トップの週間カレンダーの操作

1. 空き枠をクリック → 「開始」として選ばれる
2. 同じ日の、開始から2〜4枠目で間がすべて空いている枠が「終了候補」として強調される
3. 終了候補をクリック → 予約内容の確認モーダル（日付・時間・利用時間・合計料金）
4. 「予約する」→ 予約完了。未ログインなら「ログインして予約」でログイン画面へ
5. 開始を選んだ後に別の空き枠（終了候補以外）をクリックすると、そこが新しい開始になる。空きでない枠をクリックすると選択解除
6. 開始に選んだ枠をもう一度クリックすると選択解除 **【R2】**

- グリッドの上に、今どの操作をすればよいかの案内を1行出す **【R2】**（「開始時刻の枠を選んでください（2〜4時間）」など。[08 §3.3](08-screen-design.md#33-選択中の案内selectionhint)）

- 週送り: 今週より前には戻れない。予約可能期間（1か月後）を含む週まで進める
- 枠の表示: 空き / 予約済（誰の予約かは出さない）/ 受付外（定休日・休業日・過去・期間外）
- 他の人の予約・キャンセルは、カレンダーを開いている間 **60秒ごと** に取り直して反映する（最大60秒遅れる）。自分の予約・キャンセルはすぐ反映する **【R2】**（R1 は WebSocket で数秒以内に反映していた。このアプリにそこまでの即時性は要らないので、構成を軽くする。2026-09-29 決定）

### ログイン・ログアウト後の遷移

- ログイン後: 管理者は `/admin`、会員は `/` へ
- 会員登録後: `/` へ
- ログアウト後: `/` へ **【R2】**（R1 はその場に留まった）

## 8. メール

| メール | 送るタイミング | 宛先 |
|---|---|---|
| 予約完了 | 会員が予約したとき | 予約した会員 |
| 予約キャンセル | 会員がキャンセルしたとき / 管理者が会員の予約をキャンセルしたとき | 予約した会員 |
| 施設都合キャンセル | 臨時休業日の登録で予約がキャンセルされたとき（理由入り） | 予約した会員 |

- 電話予約（`user_id = null`）にはメールを送らない
- 本文: 予約者名、予約日（曜日付き **【R2】**）、時間、料金、施設の連絡先

## 9. データ保持

- 予約日が3か月より前の予約は毎日削除する（管理画面で遡れる範囲と揃える）
