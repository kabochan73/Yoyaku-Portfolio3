# 06. テスト方針

## 方針

- **機能と同じコミットでテストを書く**
- 予約ルールは **境界値** をテストする（1時間 / 2時間 / 4時間 / 5時間、9時開始 / 10時開始 / 20時開始 / 21時開始、1か月後の当日 / 翌日 など）
- 「今」に依存するテストは時刻を固定する（backend: `$this->travelTo()`、frontend: `jest.useFakeTimers().setSystemTime()`）
- R1 からの改善点（B1〜B17）は、それぞれ **直したことを示すテストを最低1本** 書く。どのテストがどの B に対応するかは、テスト名に `B2:` のように入れて追えるようにする
- カバレッジの数値目標は置かない。下の「必ず書くテスト」を満たすことを完了の条件にする

## バックエンド（Pest）

### 実行環境

- **PostgreSQL で実行する**（R1 は SQLite のインメモリ）。排他制約・部分インデックス・`btree_gist` は SQLite に無く、二重予約防止（B2, B3）を検証できないため
- `docker compose` の `postgres` にテスト用 DB `futsal_test` を作る。CI は `services: postgres` と `services: redis` を使う
- キャッシュは Redis（テスト用の DB 番号）を使い、各テストの前に `Cache::flush()` する。`array` ドライバにしないのは、本番と同じ保存・期限の動きを確かめるため
- `RefreshDatabase` を使う。`afterCommit` のリスナーも、Laravel が `RefreshDatabase` のトランザクションを「外側」として扱うので、テスト内の commit 後に正しく動く
- テストデータは Factory の state で作る: `ReservationFactory` に `confirmed()` / `cancelled()` / `phone()`（`user_id` なし）/ `on($date, $start, $end)`

### 種類

| 種類 | 対象 | 例 |
|---|---|---|
| Unit | `Booking/`（`TimeSlot`, `BookingRules`, `PriceCalculator`, `DayClosure`）、Enum | 営業時間・利用時間の境界値、平日 / 土日の料金。`$now` を引数で渡すので DB も時刻の固定も要らない |
| Feature（参照） | `ClosedDays`, `CalendarQuery` | 定休日・休業日の判定が予約時とカレンダーで一致する（カレンダーで `available` の枠は予約でき、`closed_reason` のある日は 422） |
| Feature | API 1本ずつ | ステータスコード、レスポンスの形、DB の状態、発行されたイベント |
| Feature（DB 制約） | マイグレーションの制約 | 重なる確定済み予約を直接 INSERT すると `23P01` になる。キャンセル済みとは重なってよい |

### 必ず書くテスト

| 対象 | テスト |
|---|---|
| 予約作成 | 各ルール違反で 422 / 重なりで `409 slot_taken` / 同日2件目で `409 already_booked_that_day` / 成功で 201・料金が正しい・`ReservationCreated` が発行される |
| 電話予約 | 会員と同じルール違反で 422（1か月より先・定休日も 422）/ 同じ日に電話予約を2件作れる（1人1日1件の対象外）/ メールは送られない |
| 二重予約（B2） | Action を経由せず、同じ枠の確定済み予約を2件 INSERT → 2件目が例外になる。`CreateReservation` がその例外を `ConflictException(slot_taken)` に変換する |
| 1人1日1件（B3） | 同じ会員・同じ日の確定済み予約を直接2件 INSERT → 2件目が例外。1件をキャンセル済みにすれば2件目を作れる。電話予約（`user_id` NULL）は同じ日に何件でも作れる |
| タイムゾーン（B1） | `travelTo('2026-10-06 08:00', 'Asia/Tokyo')`（UTC では前日）で、当日の枠が予約できる |
| 過ぎた時刻（B10） | 15:00 に当日 14:00 開始は 422、16:00 開始は 201。カレンダーで 14 時の枠が `past` |
| キャンセル（B4） | 本人は 200 / 他人は 403 / キャンセル済みは 409 / 開始済みは 409 / 管理者は `/admin/...` で他人の予約をキャンセルでき、メールは「管理者によるキャンセル」の理由になる / 管理者でも会員用ルートでは他人の予約は 403 |
| 臨時休業（B7） | 予約ありで確認なし → 409 と件数 / 確認あり → 全件キャンセル・休業日作成・メールがキューに積まれる / 途中で例外 → 予約も休業日も元のまま・メール0通 |
| メール（B8） | `Mail::fake()` で、会員の予約はメールあり・電話予約はなし。ロールバックされたらキューに積まれない |
| 予約期間（B13） | `travelTo('2027-01-31')` で 2/28 は予約可・3/1 は 422。`meta.bookable_until` が `2027-02-28` |
| 当日の休業登録（B14） | 14:00 に今日を休業日にする → 10〜12時の予約（開始済み）は残り、16〜18時の予約はキャンセル。確認の件数は1件 |
| 管理カレンダー（B11） | 定休日に確定済み予約がある → `/calendar` はその日 `slots: []`、`/admin/calendar` はその枠が `booked`（`reservation_id` 付き）・他の枠が `closed`。`/calendar` は管理者が呼んでも会員と同じ内容 |
| カレンダーの ETag | `/calendar` のレスポンスに `ETag` が付く / 同じ `If-None-Match` で再度呼ぶと 304 / 予約が入った後は 200 で新しい中身 / `Cache-Control` に `private` と `no-cache` |
| 中継元の IP（B12） | `X-Forwarded-For` 付きで内部ネットワークから来たリクエストの `ip()` がクライアント IP になる。外部から来た `X-Forwarded-For` は無視される |
| フロントの再検証（B6） | 料金・定休日の更新で `RevalidateFrontendCache` がキューに積まれる。`Http::fake()` で正しい URL・Bearer トークンで呼ばれる。予約の作成では呼ばれない |
| 認可 | 管理者 API は会員で 403、未ログインで 401 |
| エラー形式（D5） | 401 / 403 / 404 / 409 / 422 が `message` と `code` を持つ |
| 施設情報 | `/facility` の `rules` が `config/facility.php` と一致する |
| 保持期間 | `model:prune` で3か月より前の予約だけが消える |
| カレンダーのキャッシュ | 2回目の `/calendar` では DB への問い合わせが0回（`DB::enableQueryLog()` で数える）/ 予約・キャンセル・電話予約・休業日の登録と削除の後、その日のキャッシュが消えて次の `/calendar` に反映される（他の日のキャッシュは残る）/ 定休日の変更で定休日のキャッシュが消える / 61秒たつと DB から読み直す / `slot_taken` で失敗したらその日のキャッシュが消える |
| 時間の判定はキャッシュしない | キャッシュが残っていても、`travelTo` で1時間進めると過ぎた枠が `past` になる |
| 予約時はキャッシュを使わない | キャッシュに「休業日ではない」が残っている状態で DB に休業日を入れる → 予約は 422 になる |
| ユーザー削除（B9） | 会員を削除しても予約は残り、`user_id` が NULL になる |
| 会員登録 | `role: "admin"` を送っても `user` で作られる（一括代入の防止） |
| プロフィール | 現在のパスワード違い → 422 で `errors.current_password` |
| レート制限 | ログインを6回/分 → 429 と `code: too_many_requests` / `GET /calendar` は同じ IP から61回/分でも 429 にならない（300回/分まで通る） |
| 予約のレスポンス | `phase` が開始前 / 利用中 / 終了で正しく変わる（`travelTo` で時刻を動かす）。`is_cancellable` は開始前だけ真 |
| ユーザー検索 | `%` を含む検索語がワイルドカードとして扱われない |

### 同時実行のテストについて

PHP のテストで本当に並行リクエストを出すのは難しいので、「制約が効いていること」を DB レベルで直接確かめる（上表の「二重予約」「1人1日1件」）。これで「アプリのチェックをすり抜けても DB が止める」ことが示せる。

臨時休業日と予約の競合（アドバイザリロック）は自動テストでは再現しにくいので、ロックを取る処理が両方の Action から呼ばれていることだけをテストし、競合そのものはコードレビューで確認する。

## フロントエンド（Jest + Testing Library + MSW）

### 方針

- R1 は hook のテストで axios をモックしていた。R2 は **MSW でネットワーク層をモック** し、`api.ts` → hook → コンポーネントを通しでテストする
- 見た目のクラス名ではなく、ロール・ラベルで要素を取る（`getByRole("button", { name: /10月6日.*12:00〜13:00 空き/ })`）
- MSW が返す JSON は `src/test/fixtures/` に置き、CI のビルド用スタブサーバーと共有する（[07](07-dev-and-deploy.md#ビルド用のスタブサーバー)）

### 必ず書くテスト

| 対象 | テスト |
|---|---|
| `features/calendar/selection.ts` | 開始選択 / 2〜4枠目が終了候補 / 1枠目・5枠目は候補外 / 間に予約済みがあると候補外 / 別の日を押すと開始し直し / 予約済みを押すと解除 / **同じ枠をもう一度押すと解除** / 営業時間の終わり（21時開始は候補なし）|
| `lib/date.ts` | `todayInTokyo()` が端末のタイムゾーンに関係なく JST の日付を返す（`TZ=America/Los_Angeles` で実行）/ 月・年またぎの `addDays` / `mondayOf` |
| `lib/api-client.ts` | 各ステータスのレスポンスが `ApiError` の `code` と `fieldErrors` に変換される / ネットワークエラーの文言 / 419 のとき CSRF Cookie を取り直して1回だけ再送する（2回目の 419 はエラーにする） |
| `lib/format.ts` | `formatDateJa`（曜日）/ `formatHourRange` / `formatYen`（3桁区切り） |
| `BookingCalendar` | 枠を2回選ぶと確認ダイアログに日付・時間・料金が出る / 予約すると一覧とカレンダーが再取得される / `409 slot_taken` でエラー表示とカレンダー再取得 |
| 定期取得 | `jest.useFakeTimers()` で60秒進めるとカレンダーが取り直される / タブが裏にある間は取り直さない / 30秒後に別の週へ行って戻ってもリクエストが出ない（`staleTime`）/ 70秒後に戻ると取り直す / 予約後は60秒以内でもすぐ取り直す |
| `ReservationCard` | `phase` に応じて「キャンセル」ボタン / 「ご利用中」/「ご利用済み」が出る |
| `/internal/revalidate` | シークレットなし・違う値は 401 / 正しい値で `revalidateTag("facility", { expire: 0 })` が呼ばれる |
| `Header` | ユーザー取得中はスケルトン（ボタンと同じ大きさ）を出す / 取得後にゲスト用・会員用・管理者用のボタンに変わる |
| `BookingCalendar`（B15） | `/calendar` が 500 → 「空き状況を取得できませんでした」と再読み込みボタンが出る。「－」の枠は出ない |
| `PriceForm` / `RegularHolidayForm`（B16） | `/facility` の応答前は保存ボタンが無い。応答後に現在値が入る |
| `AdminReservationDialog` / `CancelDialog`（B17） | キャンセルが 409 → ダイアログが開いたままエラーが出る |
| 選択中の予約済み化 | 開始に選んだ枠が定期取得の後に `booked` になる → 終了候補が0件になり「続けて空いていません」の案内が出る |
| `Dialog` | 開いたときフォーカスが中に移る / Esc で閉じる / 閉じたらフォーカスが戻る |
| フォーム | zod のエラー表示 / サーバーの 422 が項目ごとに出る |
