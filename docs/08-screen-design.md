# 08. 画面設計

画面ごとに **部品の分け方** と **状態（読み込み中・空・エラー・送信中・成功）ごとの表示** を決める。見た目（色・余白）は R1 を引き継ぎ、ここでは決めない。

## 1. 共通ルール

### 1.1 状態の出し方

| 状態 | 出し方 | R1 |
|---|---|---|
| 初回の読み込み中 | **スケルトン**（最終的な形と同じ大きさの灰色の枠）。表示されたときにレイアウトがずれないようにする | スピナー、または何も出さない |
| 別のデータへの切り替え中（週送り・検索語の変更） | **前のデータを出したまま** 薄くする。データを一瞬消さない | 「読み込み中...」のオーバーレイ（週送りのたびに全体が白くなる） |
| 同じデータの取り直し中（定期取得・タブに戻ったとき・操作後の再取得） | **何も出さない**。届いたら差し替わる | 同じ |
| 取得の失敗 | その場所に **エラー表示 + 「再読み込み」ボタン**。空や「受付外」に見せない | 表示なし。カレンダーは全部「受付外」に見えた |
| データが空 | 空であることを文章で出す（「今後の予約はありません」） | 同じ |
| 送信中 | 送信ボタンを無効にし、文言を「〜中...」に。二重送信を防ぐ | 同じ（一部のボタンは無効化漏れ） |
| 送信の失敗 | **操作した場所のすぐ近く** に出す。ダイアログ内の操作ならダイアログを閉じずに中に出す | ダイアログを閉じてしまい、エラーが見えない箇所があった |
| 送信の成功 | 結果が画面に反映されること自体を成功の合図にする。設定の保存のように見た目が変わらないものだけ「保存しました」を出す（次に入力を変えたら消す） | 同じ |

- **取得の失敗を「データが無い」と区別する**のが最重要。R1 はカレンダーの取得に失敗すると `getSlotStatus` が `"closed"` を返し、全部の枠が「－」になって「今週は全部埋まっている / 休み」に見えた（**B15**）
- エラーの文言は `ApiError.message`（サーバーの `message`）をそのまま出す。ネットワークエラーは「通信に失敗しました。時間をおいて再度お試しください。」（[05](05-frontend-design.md#libapi-clientts)）
- 項目ごとのエラー（422 の `errors`）は、その入力欄の下に出す。R1 は登録画面で最初の1件だけ、プロフィールでは `message` だけを出していた

### 1.2 フォームの読み込み待ち

**サーバーの現在値を編集するフォームは、値が届くまで操作させない。**

- R1 の料金設定は、読み込み前に「保存する」を押すと空欄が `Number("")` = **0円で保存された**。定休日設定も、読み込み前に保存すると **定休日が全部消えた**（**B16**）
- R2 は値が届くまでフォームの代わりにスケルトンを出し、届いたら `useForm({ values })` で入れる。R1 の `key` を変えて作り直す書き方はやめる

### 1.3 ダイアログ

- 共通の `Dialog`（`<dialog>` + `showModal()`、[05](05-frontend-design.md#ui-部品)）を使う
- 送信中は Esc・背景クリック・「閉じる」で閉じられないようにする（送信結果を見失わないため）
- 送信に失敗したら **ダイアログを開いたまま** エラーを中に出す（**B17**）
- 成功したら閉じる。閉じた後、フォーカスはダイアログを開いたボタンに戻る。ただしそのボタンが消えている・押せなくなっている場合は、成功メッセージ（無ければ一覧の見出し）に移す
  - 例: 予約した枠は `booked` で押せなくなるので、フォーカスは「予約しました」のメッセージへ。キャンセルした予約の行は消えるので「予約をキャンセルしました」のメッセージへ

### 1.4 日付・時刻・金額の表記

| 対象 | 表記 | 関数 |
|---|---|---|
| 日付（長い） | `2026年10月6日（火）` | `formatDateJa` |
| 日付（短い、週の範囲） | `10/5 〜 10/11` | `formatWeekRange` |
| 時刻 | `12:00 〜 14:00` | `formatHourRange` |
| 金額 | `¥8,000` | `formatYen` |

- R1 は管理画面の臨時休業日一覧で `2026-10-06` のまま表示していた。全画面で上の表記にそろえる
- これらの関数は `lib/format.ts` に置き、R1 のように画面ごとにコピーしない

## 2. 共通レイアウト

```
app/layout.tsx
├── Header

app/(site)/layout.tsx

```

### Header

| 状態 | 右側の表示 |
|---|---|
| 読み込み中 | ボタン2つ分のスケルトン |
| ゲスト | 「ログイン」「新規登録」 |
| 会員 | 「マイページ」「ログアウト」 |
| 管理者 | 「管理者ページ」「ログアウト」 |
| ユーザー取得の失敗 | ゲストと同じ表示にする（ヘッダーでエラーを出しても利用者にはどうしようもない。保護されたページはサーバー側で判定済み） |

- ログアウト中はボタンを無効にする。成功したら `/` へ移動する（R1 はその場に留まり、マイページにいると何もない画面が残った）
- トップは静的ページなので、ユーザーはブラウザで取る（[05](05-frontend-design.md#ヘッダーのログイン表示)）

### Footer

- 施設名・電話番号・受付時間・メール・住所を `getFacility()` から出す。R1 は Hero・Footer・メールにそれぞれ直書きしていて、電話番号が食い違っていた（D14）
- `(site)/layout.tsx` で取得する。トップ（静的）とマイページ（アクセスごと）の両方で使う

## 3. トップ（`/`）

```
page.tsx（Server Component、静的）
└── FacilityProvider(facility)
    ├── Hero                  … 施設名・キャッチ・電話・住所・メール
    ├── FacilityInfo          … 営業時間・料金・定休日・利用時間・レンタル・支払い
    ├── BookingCalendar       … "use client"
    │   ├── WeekNavigator
    │   ├── CalendarGrid
    │   │   └── SlotCell × (12 × 7)
    │   ├── SelectionHint     … 「開始時刻を選んでください」など
    │   └── ReservationConfirmDialog
    └── RulesSection          … 利用規約（01 §5 の文言）
```

- `Hero` / `FacilityInfo` / `RulesSection` は Server Component。静的 HTML に入る
- `FacilityInfo` の営業時間・利用時間の表示も `facility.rules` から作る（R1 は `"10:00〜22:00"` などを直書き）

### 3.1 BookingCalendar の状態

| 状態 | 表示 |
|---|---|
| 初回読み込み中 | グリッドの枠（曜日・時刻の見出し）は出し、枠のセルをスケルトンにする |
| 週送り中 | 前の週のセルを出したまま薄くする（`placeholderData: keepPreviousData`）。見出しの日付は新しい週に変える |
| 取得の失敗 | グリッドの代わりに「空き状況を取得できませんでした」+「再読み込み」ボタン（B15） |
| 定期取得（60秒ごと）で再取得中 | 何も出さない（勝手に変わってよい） |

### 3.2 枠の表示

| 状態 | PC | スマホ | 押せるか |
|---|---|---|---|
| `available` | 空き | 空 | ○ |
| 開始に選択中 | 開始 | 空（強調） | ○（押すと解除） |
| 終了候補 | 空き（強調） | 空（強調） | ○ |
| `booked` | 予約済 | ✕ | × |
| `past` / 受付外の日 | － | － | × |

- 枠は `<button>`。押せない枠は `disabled`。`aria-label` は「10月6日（火）12:00〜13:00 空き」の形
- R1 は開始を選んだ枠をもう一度押しても何も起きなかった（`isValidEnd` が偽 → 空き枠なので開始のまま）。R2 は **同じ枠を押したら選択解除**（[05 の `selectSlot`](05-frontend-design.md#枠選択のロジックを純粋関数にする) に含める）

### 3.3 選択中の案内（SelectionHint）

R1 は操作方法の説明が見出しの「クリックで予約！」だけで、「2〜4時間」のルールは施設情報を読まないとわからなかった。グリッドの上に1行で出す。

| 状態 | 文言 |
|---|---|
| 未選択 | 開始時刻の枠を選んでください（{min}〜{max}時間） |
| 開始を選択中 | 終了時刻の枠を選んでください。{開始}から{min}〜{max}時間まで選べます |
| 開始を選択中で、終了候補が1つも無い | この時間からは{min}時間以上続けて空いていません。別の枠を選んでください |

- 文言の `{min}` `{max}` は `facility.rules` から入れる
- 画面読み上げ向けに `aria-live="polite"`

### 3.4 選択中にデータが変わったとき

**特別な処理はしない（R1 と同じ。2026-09-29 決定）。** 選択は残したまま、表示だけ最新のデータに変わる。

- 開始に選んでいた枠が `booked` になった場合: 終了候補の判定は「開始〜終了がすべて `available`」なので、候補が1つも出なくなる。案内は「この時間からは{min}時間以上続けて空いていません。別の枠を選んでください」になり、利用者は自然に選び直せる
- 終了候補の途中が `booked` になった場合: その先の枠が候補から外れるだけ
- 確認ダイアログを開いた後に埋まった場合: 送信すると `409 slot_taken` になる（3.6）
- `selectSlot` / `canBeEnd` は毎回最新の `getStatus` で判定する純粋関数なので、データが変わっても矛盾しない

### 3.5 週送り

- 「← 前の週」: 今週より前には戻れない（`disabled`）
- 「次の週 →」: `meta.bookable_until` を含む週より先には進めない（B13）
- 週を変えたら選択は解除する
- ボタンは `disabled` 属性を使う（R1 は `aria-disabled` + クリック時の判定で、見た目は薄いが押せた）

### 3.6 ReservationConfirmDialog

```
予約内容の確認
  日付      2026年10月6日（火）
  時間      12:00 〜 14:00
  利用時間  2時間
  合計料金  ¥8,000
  [エラー表示]
  [戻る] [予約する / ログインして予約]
```

| 状態 | 表示・動作 |
|---|---|
| 未ログイン | 「予約にはログインが必要です」+ ボタン「ログインして予約」→ `/login` へ移動 |
| 送信中 | 「予約中...」。閉じられない |
| 成功 | ダイアログを閉じ、カレンダーの上に「予約しました。確認メールをお送りしました。」+「マイページで確認」リンクを出す（R1 は閉じるだけで、予約できたか分かりにくかった）。メッセージは次に枠を選ぶか週を変えるまで出しておく |
| 422 | ダイアログ内にエラー（例: 開始時刻を過ぎています） |
| 409 `slot_taken` | ダイアログ内に「その時間帯は先に予約されました」。カレンダーを取り直す。「予約する」は押せなくする |
| 409 `already_booked_that_day` | ダイアログ内に「この日はすでにご予約があります（1日1件まで）」+「マイページで確認」リンク |

- 料金は `useFacility()` の単価から計算した見積もり。確定の金額はサーバーが計算し、完了時の表示と確認メールに使う（[05](05-frontend-design.md#ブラウザ側)）

## 4. ログイン（`/login`）・会員登録（`/register`）

```
(auth)/layout.tsx（ログイン済みならリダイレクト）
├── login/page.tsx    → LoginForm
└── register/page.tsx → RegisterForm
```

| 状態 | 表示・動作 |
|---|---|
| 送信中 | ボタン「ログイン中...」「登録中...」 |
| 422（ログイン） | フォームの上に「メールアドレスまたはパスワードが正しくありません」 |
| 422（登録） | **項目ごと** に出す（メールの重複はメール欄の下）。R1 は最初の1件だけを下に出していた |
| 429 | フォームの上に「試行回数が多すぎます。しばらくしてからお試しください」 |
| 成功 | ログイン: 管理者 → `/admin`、会員 → `/`。登録: `/` |

- 入力欄は `<label htmlFor>` で結びつける（R1 は `label` と `input` が結びついていなかった）
- `autocomplete` を付ける: `email`, `current-password`, `new-password`, `name`

## 5. マイページ（`/mypage`）

```
mypage/layout.tsx（会員のみ）
└── page.tsx
    ├── MyReservationList
    │   └── ReservationCard × n
    │       └── CancelDialog
    └── Accordion「プロフィール設定」
        └── ProfileForm
```

### 5.1 MyReservationList

| 状態 | 表示 |
|---|---|
| 読み込み中 | カード2枚分のスケルトン |
| 失敗 | 「予約を取得できませんでした」+「再読み込み」 |
| 空 | 「今後の予約はありません」+「空き状況を見る」（トップのカレンダーへのリンク） |
| あり | 日付順のカード |

### 5.2 ReservationCard

```
2026年10月6日（火）
12:00 〜 14:00（2時間）
¥8,000
                          [キャンセル]
```

- `is_cancellable` が偽（今日の、開始済みの予約）はボタンを出さず、`phase` に応じて「ご利用中」（`in_use`）/「ご利用済み」（`finished`）と表示する（C2）
  - R1 は今日の予約なら終わった後でもキャンセルボタンが出ていた
- 一覧は API の `/user/reservations`（今日以降の確定済み）をそのまま使う

### 5.3 CancelDialog

```
予約をキャンセルしますか？
  日付 / 時間 / 利用時間 / 料金
  [エラー表示]
  [戻る] [キャンセルする]
```

| 状態 | 表示・動作 |
|---|---|
| 送信中 | 「キャンセル中...」。閉じられない |
| 成功 | 閉じる。一覧から消える。一覧の上に「予約をキャンセルしました」 |
| 409 `reservation_not_cancellable` | ダイアログ内に「この予約はキャンセルできません（開始済み、またはキャンセル済み）」。一覧を取り直す |

- ボタンの文言: R1 はダイアログの「閉じる」が「キャンセル」で、「予約のキャンセル」と紛らわしかった。閉じる側は **「戻る」** にする（予約確認ダイアログの閉じるボタンも同様に「戻る」）
- キャンセル料の注意書きは出さない（キャンセル料は取らない。01 C4）

### 5.4 ProfileForm（管理画面と共通）

| 状態 | 表示・動作 |
|---|---|
| 初期値 | 名前・メールは現在の値。パスワード欄は空 |
| 送信中 | 「更新中...」 |
| 422 | 項目ごと（現在のパスワード違いは「現在のパスワード」欄の下） |
| 成功 | 「プロフィールを更新しました」。パスワード欄を空に戻す。ヘッダーのユーザー情報も更新される |

- R1 は「現在のパスワードが正しくありません」を項目ではなく全体のメッセージで返していた。R2 はバックエンドで `current_password` の項目エラーとして返す（[03](03-api.md) の 422 形式）

## 6. 管理画面（`/admin`）

R1 と同じく1ページ構成。カレンダーを上に常に出し、設定はアコーディオン（開いたときに初めて中身を読み込む）。

```
admin/layout.tsx（管理者のみ）
└── page.tsx
    ├── AdminCalendar
    │   ├── WeekNavigator
    │   ├── CalendarGrid（予約済みの枠に予約者名）
    │   ├── SelectionHint
    │   ├── AdminReservationDialog     … 予約詳細・キャンセル
    │   └── PhoneReservationDialog     … 電話予約の登録
    ├── Accordion「料金設定」       → PriceForm
    ├── Accordion「定休日設定」     → RegularHolidayForm
    ├── Accordion「臨時休業日」     → HolidayManager
    │                                  ├── HolidayForm
    │                                  ├── HolidayList
    │                                  └── HolidayConflictDialog
    ├── Accordion「ユーザー検索」   → UserSearch
    └── Accordion「プロフィール設定」→ ProfileForm
```

### 6.1 AdminCalendar

データは `/admin/calendar` の1本（1週間 = 1リクエスト）。枠の状態と予約の詳細（予約者名・電話予約か・料金など）がまとめて届く。

| 状態 | 表示 |
|---|---|
| 読み込み中・週送り・失敗 | トップの BookingCalendar と同じ（3.1） |

枠の表示（トップとの違いだけ）:

| 状態 | 表示 | 押したとき |
|---|---|---|
| `booked` | **予約者名**（`is_phone` なら名前の前に「☎」） | AdminReservationDialog（`reservation_id` で日ごとの `reservations` から引く） |
| 受付外の日の `booked`（B11） | 予約者名（受付外の色の上に） | AdminReservationDialog |
| 受付外の日の `closed` | － | 何もしない |
| `available` | 空き | 電話予約の開始・終了の選択 |

- 週送りの範囲: 前は3か月前の週まで、次は制限なし（R1 と同じ）
- 選択中にデータが変わったときの扱いはトップと同じ（3.4）
- 受付外の日は見出しに理由を小さく出す（「定休日」「休業日」）。R1 は「－」だけで理由がわからなかった

### 6.2 AdminReservationDialog

```
予約詳細
  予約者 / 種別（会員・電話）/ 日付 / 時間 / 料金
  [エラー表示]
  [閉じる] [この予約をキャンセル]
```

| 状態 | 表示・動作 |
|---|---|
| 開始済み（`is_cancellable` が偽） | キャンセルボタンを出さない |
| キャンセル中 | 「キャンセル中...」。閉じられない |
| 成功 | 閉じる。カレンダーから消える |
| 失敗 | **ダイアログ内** にエラー（B17。R1 は失敗しても閉じてしまい、エラーが見えなかった） |

- 会員の予約をキャンセルすると会員にメールが届く旨を、ボタンの上に小さく出す（「会員にキャンセルのメールが送られます」）。電話予約では出さない

### 6.3 PhoneReservationDialog

```
電話予約の登録
  日付 / 時間 / 利用時間 / 合計料金
  予約者名 [          ]
  [エラー表示]
  [戻る] [登録する]
```

- 予約者名は必須・255文字以内。React Hook Form + zod（R1 は `useState` で手管理）
- 開いたら予約者名の欄にフォーカス。Enter で送信
- エラーはトップの予約確認ダイアログと同じ（409 `slot_taken` など）

### 6.4 PriceForm

| 状態 | 表示・動作 |
|---|---|
| 読み込み中 | 入力欄2つ分のスケルトン。**保存ボタンを出さない**（B16） |
| 失敗 | 「料金を取得できませんでした」+「再読み込み」 |
| 入力 | 平日・土日（円/時間）。0以上の整数。空欄は項目エラー |
| 保存中 | 「保存中...」 |
| 成功 | 「保存しました。トップページにも反映されました」 |

- 値の元は `useFacility()`（`/facility`）。保存に成功したら、レスポンス（更新後の施設情報）で置き換える（[05 の表](05-frontend-design.md#更新後に取り直すデータ)）

### 6.5 RegularHolidayForm

- 曜日7つのトグルボタン（`aria-pressed`）
- 読み込み中・失敗・保存は PriceForm と同じ（B16）
- 既存の予約がある曜日を定休日にしても、予約はキャンセルされない（01 §6.3）。保存ボタンの上に「すでに入っている予約はキャンセルされません」を常に出す

### 6.6 HolidayManager

**HolidayForm**: 日付（今日以降。`<input type="date" min={today}>`）+ 理由（任意）+「休業日を追加」

| 結果 | 表示・動作 |
|---|---|
| 201 | フォームを空に戻し、一覧に追加 |
| 409 `holiday_has_reservations` | HolidayConflictDialog を開く |
| 409 `holiday_already_exists` | 日付欄の下に「すでに休業日として登録されています」 |
| 422 | 項目ごと |

**HolidayConflictDialog**:

```
この日には予約が2件あります
  休業日にすると、2件の予約をすべてキャンセルし、
  会員の方には施設都合のキャンセルメールを送ります。
  [戻る] [予約をキャンセルして休業日にする]
```

- R1 のボタンは「強制設定する」で、何が起きるのかが分かりにくかった。起きることをそのまま書く
- 承認したら `cancel_reservations: true` で再送（[03](03-api.md#post-adminholidays)）。送信中・失敗は 1.3 のとおり

**HolidayList**: 今日以降の休業日を日付順に

| 状態 | 表示 |
|---|---|
| 読み込み中 | 行2つ分のスケルトン |
| 空 | 「登録された休業日はありません」 |
| 行 | `2026年10月10日（土）— 設備点検` + 「削除」 |

- 「削除」は確認ダイアログを挟む（R1 は1クリックで消えた）。「休業日を解除しますか？キャンセルした予約は元に戻りません」

### 6.7 UserSearch

| 状態 | 表示 |
|---|---|
| 未入力 | 「名前またはメールアドレスで検索できます」 |
| 入力中（300ms 待つ） | 何も変えない |
| 検索中 | 前の結果を出したまま薄くする |
| 失敗 | 「検索できませんでした」+「再試行」 |
| 0件 | 「該当するユーザーはいません」 |
| あり | 名前・メール・予約件数。20件ちょうどのときは「上位20件を表示しています。条件を絞ってください」 |

- デバウンスは `useDebouncedValue` として `lib/` に置く（R1 は hook 内に直書き）

## 8. ページタイトル

`metadata` で設定する。R1 は全ページ「フットサルコート予約」だった。

| ページ | `<title>` |
|---|---|
| `/` | FUTSAL PARK｜屋内フットサルコートの予約 |
| `/login` | ログイン｜FUTSAL PARK |
| `/register` | 会員登録｜FUTSAL PARK |
| `/mypage` | マイページ｜FUTSAL PARK |
| `/admin` | 管理画面｜FUTSAL PARK |

施設名は `generateMetadata` で `getFacility()` から取る（D14。施設名を画面・メールと同じ1か所から出す）。`getFacility()` の fetch はキャッシュ（タグ `facility`）されるので、タイトルのために API への問い合わせが増えることはない。`/admin`・`/mypage` は `robots: { index: false }`。

## 9. スマホ表示

R1 の方針を引き継ぐ。

- カレンダー: 時刻の列は `10:00` だけ（PC は `10:00〜11:00`）、枠は「空 / ✕ / －」の1文字
- 管理カレンダーの予約者名はスマホでは先頭2文字 + 「…」。押せば詳細で全体が見える
- ダイアログは画面幅いっぱい（左右 16px の余白）
- 横スクロールはカレンダーの中だけで起こし、ページ全体は横にはみ出さない

## 10. 部品の一覧

画面をまたいで使う部品。`components/ui/` は機能を知らない部品、`features/*/components/` は機能の部品。

各部品が Server Component か Client Component かは [05 の振り分け](05-frontend-design.md#振り分け) を参照。

| 部品 | 置き場所 | 使う画面 |
|---|---|---|
| `Button`, `Dialog`, `Accordion`, `FormField`, `Skeleton`, `Alert`, `ErrorState`（エラー文 + 再読み込み） | `components/ui/` | 全体 |
| `WeekNavigator`, `CalendarGrid`, `SlotCell`, `SelectionHint` | `features/calendar/components/` | トップ・管理 |
| `ReservationSummary`（日付・時間・利用時間・料金の表） | `features/reservations/components/` | 予約確認・キャンセル確認・予約詳細・電話予約（R1 は4つのモーダルにコピーされていた） |
| `ProfileForm` | `features/auth/components/` | マイページ・管理 |
